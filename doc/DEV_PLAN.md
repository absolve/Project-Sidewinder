# Project-Sidewinder 开发计划

> 状态：**初版（活文档）**，随里程碑推进增补/调整，不把估算当承诺。
> 计划版本：v0.2 ｜ 更新日期：2026-11-13
> 依据：`doc/GAME_DESIGN.md` v0.32（尤其 §9 v0.1 垂直切片）、`doc/CODE_GUIDELINES.md`
> 维护方式：每完成一个里程碑更新 §7 状态表与 §9 变更记录；设计规则变化回写 `GAME_DESIGN.md`，本文件不复制数值。

---

## 1. 计划口径

- **单人开发**：工期用「人日」估算，不含外包美术/音频的等待时间；不排绝对日期，避免把估算当承诺。
- **顺序推进**：v0.1 的 M0→M6 基本串行；v0.2 之后允许小步并行（如美术管线验证与玩法开发并行）。
- **完成定义（DoD）**：每个里程碑必须同时满足——
  1. 从 `main.tscn` 启动可运行，无 Parse Error / 运行时报错；
  2. 验收标准可手动复现；
  3. Godot headless 导入验证通过（命令见 `CODE_GUIDELINES` §6.1）；
  4. 新增/变更规则已回写 `GAME_DESIGN.md`；
  5. 未完成项进入 §8 Backlog，不留在代码里当隐式 TODO。
- **范围优先于日期**：进度落后时按 §6.4 的顺序砍范围，不砍验收标准。
- **变更方式**：直接改本文件并在 §9 记录；重大方向变化先在 `GAME_DESIGN.md` 拍板，再改计划。

## 4. v0.1 里程碑详情

### M0 工程底座（2–3 人日）

**目标**：工程能启动、能进灰盒、能读配置，后续系统有地方落。

**做**：
- `project.godot` 补输入动作：`switch_weapon_1/2/3`、`salvage`、`restart`（键位按 `GAME_DESIGN` §4.10）。
- `Game` Autoload 骨架：`mode / level_id / loadout / run_stats / rng_seed`，以及 `gotoScene()` / `restartLevel()` 空实现。
- 基础场景：`tank_base`、`turret_base`、`projectile_base`、`enemy_base`、`destructible_base`、`wall_base`（先空脚本 + 碰撞体 + 分组；`wall_base` 带静态/动画两种变体）。
- `DataLoader` 骨架 + `data/levels/greybox.json`（先最小字段：id/map_scene/player_spawn/areas/objectives）。
- 灰盒关卡 `scenes/level/greybox.tscn`：2–3 区域、`Ground` 仅背景、`Walls` 用 `wall_base` 实例、Spawn 标记、CameraBounds。

**不做**：正式美术、正式关卡、存档写入、商店、技能、迷雾。

**交付物**：可启动的灰盒场景 + 6 个基础场景 + 输入映射 + JSON 加载日志。

**验收**：
- 启动进入灰盒，无报错；
- 1/2/3/F/R 均能触发输入事件（可打印验证）；
- JSON 能加载并通过必填字段校验；
- 墙体实例能挡玩家/子弹；动画门能手动开合且关闭时恢复碰撞。

**风险**：基础场景过度设计。只保留 v0.1 用得到的节点，后续按需加。

---

### M1 移动、相机与射击（4–6 人日）

**目标**：玩家能开车、瞄准、开火、打中东西。

**做**：
- `CharacterBody2D` 移动/碰撞/车体转向（`GAME_DESIGN` §4.8）。
- `Camera2D` 跟随/20% 前瞻/边界钳制/震屏，`zoom = (1,1)`。
- 单炮塔瞄准、炮塔转速、≤5° 才开火（§4.2）。
- 基础机枪炮塔 + 基础炮塔；子弹线段命中；伤害/护甲/暴击/溅射基础结算。
- 最小 HUD：生命、当前武器、弹药、准星。

**不做**：敌人、掉落、武器切换、目标、可破坏物。

**验收**：
- 灰盒内移动手感与相机边界正常；
- 打固定靶有伤害、闪白、击退；
- 稳定 60 FPS。

**风险**：子弹穿模/开火对准延迟。用线段检测 + 5° 阈值实测调整。

---

### M2 敌人与掉落（4–6 人日）

**目标**：战场有威胁、有击杀、有战利品。

**做**：
- 4 种敌人节点式 FSM：爬行者 / 机枪吉普 / 霰弹突击车 / 固定炮塔（`GAME_DESIGN` §4.7）。
- 精英变体 1 种（换色 + 生命/伤害倍率）。
- 感知、追击、攻击、走位、受击/死亡状态。
- 死亡掉落携械/弹药箱；击杀信号；子弹/敌人对象池。
- 简单生成器：按标记点生成，不做分区流场。

**不做**：分区流场、警戒增援、Boss、多区域寻路。

**验收**：
- 4 种敌人行为符合 §4.7；
- 击杀掉落可拾取；
- 同屏 50 敌人无明显掉帧。

**风险**：AI 状态机过度复杂。先 5 个状态跑通，再按需拆。

---

### M3 武器栏与夺械（4–6 人日）

**目标**：单炮塔 + 3 格武器栏 + 夺械循环闭环。

**做**：
- 武器栏 3 格：1 基础保底 + 2 缴获；1/2/3 切换 0.3s（`GAME_DESIGN` §5.3）。
- 空弹自动切下一把；全空回落保底格；手动切空弹标红。
- 拾取/替换/粉碎；弹药箱；4 类弹药储备与上限。
- 4 把缴获武器：双联机枪 / 霰弹炮 / 榴弹炮 / 电浆炮。
- 武器卡片最小 UI（名称/伤害/耗弹/弹药类型）。

**不做**：稀有度/词缀/武器库/商店/合成。

**验收**：
- 「击毁 → 掉落 → 拾取 → 切换 → 打空 → 自动回落 → 粉碎换弹」全链路可用；
- 保底格不可替换、不可粉碎。

**风险**：切换与开火输入冲突。换装 0.3s 内锁定开火。

---

### M4 目标与流程（3–5 人日）

**目标**：一局有开始、有目标、有胜负、能重开。

**做**：
- `ObjectiveManager` + `eliminate` / `seize` 两类目标（`GAME_DESIGN` §5.11）。
- 主/次目标 HUD 追踪；通关/失败/结算占位。
- 暂停/重开；`Game` 会话状态与结算载荷。
- 灰盒目标：A 区歼灭 12 个 + D 区夺取原型。

**不做**：星级/排行榜/存档/多目标类型。

**验收**：
- 两条目标可完成；主目标完成即通关；
- 玩家死亡触发失败；R 重开不残留状态；
- 目标状态可序列化。

**风险**：目标判定散落。只走信号，不写进敌人/交互物脚本。

---

### M5 破坏与反馈（3–5 人日）

**目标**：验证「破坏即探索」的最小形态，并补足战斗反馈。

**做**：
- 砖墙 / 油桶两种可破坏物（HP、掉落、爆炸连锁）。
- 命中闪白、hitstop、震屏、枪口火光、爆炸粒子占位。
- 占位音效（开火/命中/爆炸/拾取）。
- 摧毁后移除碰撞体与寻路占位（v0.1 直线 AI 下先移除碰撞）。

**不做**：矿脉/秘密墙/迷雾/采集经济。

**验收**：
- 炸墙可直接开捷径；
- 油桶连锁可炸伤多个目标；
- 反馈可感知且无性能尖峰。

**风险**：连锁爆炸递归。加伤害上限与每帧结算预算。

## 6. 横向计划

### 6.1 数据与配置

- 所有静态表用 UTF-8 JSON 放 `data/`，`snake_case` + `schema_version`（`GAME_DESIGN` §5.6）。
- 关卡几何在 `.tscn`，规则/目标/装载在 `data/levels/<id>.json`；同一场景可配多份数据。
- 每新增内容先加数据表，再写差异逻辑；不在脚本里硬编码数值。
- `DataLoader` 负责加载与引用校验；开发期失败直接报错，发布版回退默认配置并写日志。

### 6.2 测试与验证

每个里程碑至少跑一遍：

1. Godot headless 导入，确认无 Parse Error / 加载失败；
2. 启动 `main.tscn` 跑验收路径；
3. 手动检查输入、碰撞、暂停/重开；
4. 灰盒场景看 FPS 与报错输出。

v0.1 必测清单：

- [ ] 移动/相机/边界/震屏
- [ ] 单炮塔瞄准、≤5° 开火、子弹命中
- [ ] 1/2/3 切换、换装期间不能开火
- [ ] 空弹自动切换、回落保底炮塔
- [ ] 拾取/替换/粉碎/弹药箱
- [ ] 歼灭/夺取目标、通关/失败/重开
- [ ] 砖墙/油桶/连锁爆炸
- [ ] 同屏压力与 60 FPS

自动化测试后置到 v0.3 之后评估，v0.1 先以手动验收为准。

### 6.3 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 范围膨胀 | v0.1 延期 | 按 §6.4 砍范围，先保核心循环 |
| 流场/占位过度设计 | 阻塞 v0.1 | v0.1 直线追击；M9 后再接分区流场 |
| 32 方向美术成本 | 资产量翻倍 | 先 16 方向/占位图，M12 实测再定 |
| 单炮塔手感偏弱 | 玩家觉得不够爽 | 用切换/保底/武器差异补，不回到多炮塔齐射 |
| 存档坏档 | 进度丢失 | 原子写 + `.bak` + SHA-256 校验 |
| 手柄适配滞后 | 后期限定体验 | 架构留 InputMap；M13 集中适配 |
| 群怪性能 | 掉帧 | 对象池 + 0.2s 索敌 + 分帧刷新 |
| 墙体全用节点实例 | 大图节点数偏高 | v0.1 控制墙段数量；静态墙合并碰撞/后续 `MultiMeshInstance2D` 合批；只有动画/开关墙独立节点 |
| 数据 schema 变更 | 旧档/旧关失效 | `schemaVersion` + 迁移函数 |

### 6.4 范围控制（进度落后时的砍功能顺序）

从上往下砍，砍到能按时完成为止：

1. 正式美术/音效（全部用占位）
2. 油桶连锁与第二种可破坏物
3. 次目标与结算界面细化
4. 精英变体
5. 缴获武器从 4 把减到 2 把
6. 灰盒区域从 3 个减到 2 个

**不砍**：移动/射击/夺械/武器切换/胜负判定/重开/60 FPS。这些是 v0.1 的存在理由。
