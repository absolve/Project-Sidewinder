## 1. 概述

| 项 | 内容 |
|---|---|
| 项目名 | Project-Sidewinder |
| 类型 | 俯视角载具射击 × 夺械改装 × 多模式 |
| 视角 | 俯视 / 等距 2D |
| 分辨率 | 1920×1080（1080p）；玩家/敌人基准 64×64px（§6.3） |
| 操作 | WASD 移动 + 鼠标瞄准 / **单炮塔开火**（双摇杆）；数字键 1/2/3 切换武器；E 交互、F 粉碎；手柄双摇杆 + 肩键切换；可选自动瞄准辅助 |
| 引擎 | Godot 4.x（GDScript / C#） |
| 目标平台 | PC（Steam），优先适配 Steam Deck 与手柄，简中首发 |
| 游戏模式 | **故事模式（战役通关） / 挑战模式（目标关卡 + 挑战规则，故事通关后解锁的独立模式） / 割草模式（波次生存）** |
| 美术方向 | **Blockbench 低多边形建模 + 俯视角渲染输出**，偏像素风，支持换色（见 §6） |

### 一句话卖点

> 驾驶可改装的战斗载具，**从被击毁的敌人身上夺取武器、装配到自己的武器栏**；在多区域战场里完成歼灭/夺取/防守/采集目标，轰开地形挖出资源与秘密，再用突变因子与星级挑战极限，在割草潮中构筑流派活到最后。

### 设计目标

1. **玩法要新**：以「夺械改装 + 多区域目标探索 + 破坏采集」组合出区别于市面割草/坦克游戏的独特循环。
2. **博采众长**：有选择地融合其他游戏的成熟机制（见 §8 借鉴来源），但用统一的载具改装与探索系统把它们串成一个整体。
3. **一套系统、三种玩法**：故事/挑战/割草三模式共享载具、武器、成长系统，开发成本可控、体验互相补强；挑战模式在故事通关后解锁，作为独立模式承接长线。

## 2. 核心创新点（让玩法「新」的关键）

1. **夺械改装（Weapon Salvage）**
   武器主要不是「买」来的，而是**从被击毁的敌人身上夺取**、或从地图武器箱/秘密区搜刮来的。不同敌人携带不同武器，击毁即可拾取装配。→ **战斗 = 刷装备 = 探索动力**，把「射击」与「刷宝」深度绑定。

2. **模块化武器栏 + 重量/能量预算**
   载具有有限的**武器栏（1 基础保底 + 至多 2 把缴获武器）**，每件武器有重量/能耗/弹药类型；同一时刻只开火 1 把，取舍构成构筑深度。缴获炮塔装配后随玩家保留（被击败不消失），可存入武器库（上限 6）。

3. **多区域目标制挑战地图**
   挑战模式用**固定手工地图**，划分为多个可自由探索的**区域**；每关有主目标 + 多个次目标/可选区域（歼灭、夺取、防守、采集、撤离），再叠加**挑战规则**（装载限制/限时/突变因子）与星级评分。玩家自选路线与目标顺序，可选区域藏秘密、稀有武器与资源。

4. **破坏即探索 / 采集**
   轰开墙体/油桶/矿脉不只是战斗特效，更是**开捷径、揭秘密、挖资源**的探索手段；战争迷雾随探索揭开，引导找目标。

5. **基地防守作为关卡目标（按关卡组合）**
   采集资源、保护基地/发电机不是独立玩法，而是**在不同关卡里作为目标模块出现**：有的关要守基地抗波次 + 建炮塔，有的关要采集够资源再撤离，组合变化。

6. **三模式共享进度 + 挑战承接长线**
   武器库、载具底盘、天赋、货币材料跨模式共用；在挑战模式缴获的稀有武器可带进割草模式，割草解锁的天赋反哺故事与挑战。故事通关后由挑战模式承接星级、突变与排行榜的长线目标。

## 3. 三大游戏模式

> 模式关系：**故事=主线战役与教学**；**挑战=故事通关后解锁的独立模式，承接长线刷宝与高难**；**割草=差异化构筑爽局**。三者共享载具/武器/成长（§3.4）。

### 3.1 故事模式（战役通关）

- **定位**：线性叙事战役，带玩家上手并展开世界观。
- **结构**：章节制推进，每章若干关卡；关卡含剧情节点、强制目标与递进难度；通关解锁结局与奖励。
- **关卡形态**：复用多区域手工地图骨架，但目标更线性、有脚本演出与 Boss 高潮；最终区域是否有 Boss 按关卡配置（见 §5.1）。
- **装载**：准备室出生，炮塔/底盘/支援技能受关卡限制（见 §5.2、§5.7）。
- **重玩**：章节选择 + 多难度 + 三星评分 + 隐藏收集。

**世界观与主线（初版）**：

- 近未来，国民级速冻食品后勤枢纽「**三鲜水饺仓库**」（战略补给 + 自动生产线中枢）被叛乱机械军团占领；军团劫持中央控制 AI，把水饺生产线改造为军工生产线持续暴兵（解释生成器刷怪、哨戒炮与全机械敌人，§4.7）。
- 玩家是回收部队驾驶员，驾驶模块化载具**单人突入**：从仓库外围一路打到核心区域，**收复被占领的仓库**。
- 夺械的世界观依据：军团载具武器走模块化标准接口，击毁即可拆下炮塔即用（§4.1）。

**叙事弧线（三幕，初版）**：

- **第一幕（第 1–2 章）突入**：外围突破 → 站稳脚跟；教学 + 建立夺械循环。
- **第二幕（第 3–5 章）深入与揭露**：冷链/仓储/生产区逐层深入，发现 AI 被劫持、水饺生产线被改造暴兵的真相。
- **第三幕（第 6–7 章）转折与决战**：能源区断电瘫痪生产线 → 军团全面反扑（Half-Life 2 摧毁 Nova Prospekt 点燃起义式转折）→ 核心区域 Boss 决战 → 重启控制 AI → 收复仓库（单结局，多结局暂不做）。

**章节大纲（初版 7 章 × 2–3 关 = 18 关，待细化）**：

| 章 | 区域 | 关卡（关数） | 主目标 | 引入机制 | 剧情节点 |
|---|---|---|---|---|---|
| 1 | 外围防线 | 围墙突破口 / 哨站清理（2） | 歼灭 + 夺械教学 | 移动/瞄准/夺械/准备室 | 简报：三鲜水饺仓库失联；无线电支援官登场 |
| 2 | 装卸货运区 | 货运月台 / 编组站 / 停车场（3） | 歼灭 + 夺取（货单） | 破坏捷径/油桶连锁/武器箱 | 缴获货单：水饺订单被改写成军需 |
| 3 | 冷链仓储区 | 冷冻库入口 / 低温库区 / 秘密冷库（3） | 探索 + 采集 | 迷雾/秘密墙/保险箱/稀有掉落 | 日志拾取：AI 被劫持真相 |
| 4 | 仓储迷宫区 | 货架迷宫 / 高架库 / 中转仓（3） | 多区域探索 + 歼灭 | 多区域路线/捷径/采集 | 发现生产线改造痕迹 |
| 5 | 生产加工区 | 和面车间 / 速冻生产线 / 包装车间（3） | 摧毁生成器 + 基地防守 | 建造/防守波次 | 真相：速冻生产线在暴兵（生成器本体） |
| 6 | 能源动力区 | 变电站 / 锅炉房（2） | 摧毁供能 + 防守反击 | 警戒增援/限时目标 | 转折：断电瘫痪生产线，军团全面反扑 |
| 7 | 核心控制区 | 核心突入 / 主脑决战（2） | Boss 决战 | 全机制综合 | 击败核心守卫，重启 AI，收复仓库 |

**Boss 战口径（已定方向 + 初值）**：

- **每关关底都有 Boss**：故事模式每关最终区域 `final_area.has_boss=true`（挑战模式仍可配置无 Boss，§5.1 口径不变）。
- **时长下限**：每关 Boss 战**至少打 5 分钟**（300s）——18 关仅 Boss 战就 ≥90 分钟，加上探索推进保证故事流程不短。
- **血量口径**：Boss HP = 本章期望有效 DPS × 300s；期望 DPS 按章节标定（跟随玩家武器成长），以下为初值：

| 章 | 期望有效 DPS | Boss HP 初值 |
|---|---|---|
| 1 | 40 | 12,000 |
| 2 | 55 | 16,500 |
| 3 | 70 | 21,000 |
| 4 | 90 | 27,000 |
| 5 | 110 | 33,000 |
| 6 | 130 | 39,000 |
| 7 | 150 | 45,000 |

- 5 分钟是**纯输出时间下限**；实战含走位/阶段转场/清增援，时长只长不短。同章多关 Boss HP 在章基准上 ±10% 微调（初值）。
- **阶段设计**：Boss 分 3 阶段（血量 2/3、1/3 触发），转场短暂无敌 + 召唤增援 + 切换攻击模式，避免纯木桩；具体阶段机制按 Boss 配置（待设计）。
- **美术口径**：普通关 Boss = 精英模型放大 + 换色（§6.2 管线）；章末/终章 Boss 加部件差异化；18 关不新做 18 套模型。
- 平衡备注：Boss 伤害同步标定，避免「血厚但无威胁」；实测后可上调时长下限。
- **剧情演出轻量**：准备室简报 + 战斗中无线电字幕（MGS 式）+ 环境叙事（残骸/涂鸦/日志拾取物，HL2 式）；**不做过场动画**（成本口径）。
- **装载限制服务叙事**（§5.7）：第 1 章仅配发基础炮塔，夺械教学后开放装配；逐章解锁底盘/支援技能池。
- **与挑战模式的关系**：故事地图 = 仓库整体分区；故事通关后，挑战模式复用各章区域做「目标 + 规则」变体，一份手工地图资产两种用法（§3.2）。
- **通关解锁**：通关第 7 章（终章）后解锁挑战模式入口（§3.2）。
- **【待设计】**：对话脚本、Boss 机制、关卡列表细化（目标/装载/评分阈值）、演出事件清单。

### 3.2 挑战模式（目标关卡 + 挑战规则）—— 创新核心

- **定位**：故事模式通关后的**长线扩展玩法**，同时作为**独立模式**常驻主菜单。把「夺械 + 探索 + 破坏采集 + 防守」放进可配置的**挑战规则**里，用星级、评分与排行榜驱动重玩；不另起一套玩法，也不改动故事叙事。
- **解锁与入口**：
  - 正式版：通关故事模式终章（第 7 章）后解锁主菜单入口，与故事/割草并列；解锁后随时独立进入，不依赖故事存档进度。
  - 挑战关卡按故事章节区域组织（外围/货运/冷链/仓储/生产/能源/核心），复用同一批手工地图资产，换目标与规则即可产出新关。
  - **MVP/开发期直接开放入口**（不校验故事进度），先验证「目标 + 规则 + 评分」核心，不等 18 关战役做完。
- **地图**：固定手工**多区域地图**（3–6 区域），区域间有通道、可破坏捷径与秘密路径；玩家自选路线与目标顺序。
- **装载**：准备室出生；默认自由装配 ≤3 武器（1 基础保底 + 2 缴获，受底盘格数限制）/ 1 底盘 / ≤3 支援技能，**受本关挑战规则约束**（可锁定底盘/武器池/槽位/禁用商店，§5.10）。
- **通关条件（目标制，与故事共用目标模块，按关组合）**：
  - **歼灭**：清空指定区域敌人 / 击毁精英 / 摧毁生成器。
  - **夺取**：取得指定物品 / 打开武器箱 / 缴获敌方原型武器。
  - **防守**：保护基地/发电机抵御若干波次，可建炮塔工事。
  - **采集**：挖够指定资源 / 占领采集中继点。
  - **撤离**：带着战利品抵达撤离点（可选「提取」风险收益）。
  - 每关 = 1 个主目标 + 多个次目标/可选区域；完成主目标即可通关，次目标给额外奖励与评分。
- **挑战规则层（与目标正交、可叠加，详表见 §5.10）**：
  - **装载限制**：限定底盘/武器池/炮塔数/技能数、禁用商店或中途补给。
  - **限时**：关卡总时限、目标限时、撤离窗口。
  - **突变因子**：敌人等级 +1、精英比例提升、警戒增援加速、弹药掉落减半、迷雾不散、Boss 提前入场等。
  - **评分**：基础分（目标/时间/受击/收集）× 挑战等级倍率 × 突变倍率 → 1–3 星 + 排行榜。
- **难度阶梯**：挑战等级 I–V，逐级叠加固定突变与分数倍率；各等级独立记录星级与排行榜，玩家自选（同关可反复刷）。
- **武器来源**：与故事一致——击败敌人夺械（主）、地图武器箱、秘密区、准备室商店（§5.3）；挑战模式额外开放挑战专属稀有掉落池。
- **奖励与长线**：
  - 首通/星级奖励：金币、零件、挑战专属稀有武器与改装件、涂装/称号（零额外美术成本，走 §6.2 换色）。
  - **挑战星级与挑战成就作为底盘/支援技能/涂装解锁前置**（§4.8、§4.9），承接故事通关后的成长主线。
  - 每日/每周固定种子挑战：规则与突变固定、全球同题，独立排行榜。
- **重玩**：星级全清、突变组合、秘密收集、全球/好友排行榜 + 随机战利品词缀。
- **与另外两模式**：故事=线性叙事与教学；挑战=通关后的目标+规则刷宝长线；割草=程序生成构筑爽局；武器库/天赋/货币三模式共享（§3.4）。
- **【待设计】**：挑战关卡清单与解锁顺序、区域模板库、目标类型细则（防守/采集/撤离）、突变因子数值、评分公式与星级阈值、排行榜与每日/每周轮换规则、挑战专属掉落表、警戒增援规则、撤离机制。

### 3.3 割草模式（波次生存）

- **定位**：Survivors-like 爽快割草，短局高重玩，验证构筑深度。
- **结构**：程序生成战场（或固定竞技场），波次压力递增 + 精英/Boss；单局 10–15 分钟。
- **构筑**：局内升级三选一（武器词条/性能/模块）+ 波间商店买卖与同级武器合成；可用挑战模式缴获的武器入库。
- **装载**：支援技能**无数量限制**，炮塔上限可局内扩展（见 §5.7）。
- **操作**：手动瞄准为主，可选自动瞄准辅助（降低门槛）。
- **重玩**：冲分 + 全球排行榜 + 每日固定种子局 + 难度阶梯换奖励。
- **【待设计】**：波次曲线、升级池、合成规则、排行榜/种子规则。

### 3.4 模式间共享进度

- **共享**：武器库、载具底盘、模块/天赋、货币与材料、解锁进度。
- **差异**：故事=线性叙事；挑战=通关后手工地图 + 挑战规则刷宝；割草=程序生成波次构筑。
- **进度接力**：故事提供解锁与教学 → 挑战承接故事通关后的长线与高难刷宝（星级/排行榜/突变）→ 割草提供差异化构筑爽局；挑战星级与挑战成就同时作为部分底盘/技能解锁前置。
- **经济统一**：金币 + 零件双货币（§4.6），缴获/采集/击杀所得进入统一账户，用于改装与解锁。

## 4. 共享核心系统

### 4.1 载具模块化改装 + 夺械
- 载具分 **底盘 / 炮塔位 / 模块** 三类槽位：**车体只有 1 个炮塔挂载位（单炮塔开火），武器栏最多携带 3 把武器**（含基础炮塔）；切换武器即换装，同一时刻只有当前武器存在并开火（见 §5.3）。携带的武器共用重量/能量预算。
- 武器从敌人/武器箱/秘密区/商店缴获；装配后随玩家保留，可存入武器库（见 §5.3）。
- 模块提供被动协同（如「弹药回收」「过热减免」「采集加成」「炮塔强化」），槽位间互锁产生流派。
- 载具基础属性与底盘见 §4.8，支援技能清单见 §5.5。**【待设计】**：武器栏重量/能量预算细则、模块清单、协同规则、数值平衡、夺械掉落率表。

**夺械流程（核心：击败敌人 → 掉落炮塔）**：

1. **掉落**：每种敌人配置「携带炮塔」（见 §4.7），被击毁时掉落为地面实体拾取物，带稀有度光效。
   - 普通敌人低概率掉落（初值 30%），稀有度按敌人等级表（§4.7）；精英必掉且按等级 +1；Boss 必掉按 Lv5。
   - **弹药箱**：敌人被击毁时**独立概率掉落弹药箱**（初值 30%，与炮塔掉落互不影响）；类型按敌人携械弹药（不发射/无携械类随机一类）；接触自动拾取，补充该类型弹药上限的 15%（向上取整、不超上限，初值）；精英/Boss 必掉 1 个。
   - 掉落物关卡内不消失；拾取装配后随玩家保留，被击败不消失（见 §5.3）；未拾取就退出则留在关卡。
2. **拾取与装配**：靠近 + 交互键拾取（初值，可配置接触自动装配）。
   - 武器栏有空位 → 直接装配；武器栏已满（3 把）→ 选择换下哪把，旧炮塔丢在原地可再捡。
   - **也可选择粉碎**：不拾取，直接粉碎掉落炮塔换取对应弹药（见下方粉碎规则）。
3. **装配使用**：缴获炮塔装配后与武器库炮塔同权，按弹药大类共享储备（见 §4.5）；**只有当前选中的 1 把武器开火**，切换武器即换装（§5.3）；当前武器空弹自动切到下一把有弹的武器；全部耗弹武器打空时回落到基础炮塔（不耗弹、永不空缺），不会弹尽卡死。
4. **保留与入库**：身上武器通关/被击败均保留；可存回武器库（上限 6，见 §5.3），满库拆解为零件（见 §4.6）；武器库三模式共享（见 §3.4）。
5. **可选深度（暂不实装）**：参考 BattleTech「击毁方式影响打捞质量」——过度击毁（爆炸系）可能损坏掉落物，精准击杀保全；先验证核心循环再考虑。

**粉碎规则（初值）**：

- **交互**：掉落物拾取 / 粉碎二选一（初值：E 拾取、F 粉碎，输入映射实装时定）；粉碎后炮塔销毁，不可恢复。
- **返还弹药**（按炮塔弹药类型，基础量初值）：

| 弹药类型 | 基础返还 |
|---|---|
| 机枪子弹 | +30 |
| 普通炮弹 | +6 |
| 能量弹药 | +10 |
| 建筑弹药 | +5 |

- **稀有度倍率**：白 ×1 / 绿 ×1.2 / 蓝 ×1.5 / 紫 ×2 / 橙 ×3（向下取整）；备选弹药类未独立时按普通炮弹返还（§4.5）。
- **底盘加成**：采集底盘粉碎获取 **+50%**（§4.8）；其他底盘/模块后续可扩展。
- **定位**：关卡内弹药主要来源 +「要武器还是要弹药」的现场抉择；与武器库拆解明确区分——**现场粉碎得弹药，武器库拆解得零件**（§4.6）。

> 借鉴口径：RUINER「敌人 constant 掉武器、武器即消耗品」→ 取战斗=刷装备与频繁换装节奏，耐久简化为弹药约束；Panzer Paladin「夺取敌械」→ 取敌人为武器主要来源，折断成长暂不采纳；MechWarrior/BattleTech「战后残骸打捞」→ 取带回武器库永久入库（见 §8）。

**弹道与伤害结算（基础规则，初版）**：

- **瞄准与开火**：鼠标位置 = 世界瞄准点；炮塔按「炮塔转速」（§4.8）转向瞄准点，**与瞄准方向夹角 ≤5° 才开火**（按住开火键时自动等对准，不用反复点）。车体朝向与炮塔独立。
- **命中检测**：所有飞行弹每物理帧从「上一位置 → 新位置」做线段检测，命中最近的有效目标；高速弹不会穿模。激光/轨道炮走即时线段（hitscan），抛物弹走「预定落点 + 到时范围检测」，追踪弹每帧转向后同样做线段检测。
- **弹速与寿命（初值）**：机枪弹 1200 px/s / 0.6s；普通炮弹 700 px/s / 1.6s；能量弹 600 px/s / 1.2s；火箭 450 px/s / 3s（转向 180°/s）；激光/轨道炮即时。寿命到即消失（可配置为落地消失或空爆）。
- **伤害类型**（与弹药大类正交，独立字段）：
  - `direct` 直击：子弹/炮弹/激光等直接命中。
  - `explosion` 爆炸：榴弹/电浆/地雷/油桶/爬行者自爆等范围伤害。
  - `contact` 碰撞：冲撞车接触、碾压等。
  - 用途：**绝境防爆只免疫 `explosion`**（§5.5）；铁丝网等免疫按 `ammoType` 判定（§4.3）。两者不可混用。
- **溅射**：以爆心为圆心，中心 100% → 边缘 40% 线性衰减；初值半径——基础炮塔 64px、榴弹炮 96px、电浆炮 80px、地雷/油桶 96px（各武器可在数据表覆写）。**爆心必须有视线才结算**；爆心确定后，范围内目标不再做遮挡判定（v0.1 简化）。
- **护甲与穿透**：敌人护甲为百分比减伤（0–80%）；穿甲炮/轨道炮**无视 50% 护甲**（初值），其余武器全额吃护甲；「硬壳」突变 +30% 护甲（§5.10）。
- **暴击**：基础暴击率 0%，仅词缀提供（+5~10%），暴击伤害 ×2；对直击与爆炸统一生效。
- **伤害公式**：`最终伤害 = max(1, round(基础伤害 × 稀有度加成 × 词缀加成 × 暴击倍率 × (1 - 护甲)))`；固定伤害与百分比减伤先乘后减，避免负伤害。
- **自伤与友伤（v0.1 简化）**：玩家自己的武器爆炸不伤玩家；油桶等**环境爆炸**对敌我双方都造成伤害（鼓励远程引爆）；敌方爆炸正常伤玩家。
- **受击反馈**：命中闪白 0.08s；击杀触发 0.05s 命中停顿（hitstop）；伤害数字默认关闭（设置可开）。装填/过热 v0.1 不做，仅弹药储备 + 开火延迟；后续按 §4.5 接入。
- 结算统一走 `hit(damage, attackPos, knockDir, ammoType, damageType)`；签名见 `doc/CODE_GUIDELINES.md` §2.4。

**稀有度体系（初版，参考 Borderlands + Diablo）**：

参考口径：Borderlands 用白→绿→蓝→紫→橙颜色分级，传奇特效改变玩法而不只是数值高；Diablo 词缀数量随稀有度递增、传奇带固定威能。本项目取两者结合：**5 档颜色 + 词缀数递增 + 传奇固定特效**。

| 稀有度 | 颜色 | 随机词缀数 | 伤害基准加成 | 主要来源 |
|---|---|---|---|---|
| 普通 | 白 | 0 | +0% | 普通敌人、商店 |
| 精良 | 绿 | 1 | +5% | 普通敌人、商店 |
| 稀有 | 蓝 | 2 | +10% | 精英、武器箱 |
| 史诗 | 紫 | 3 | +15% | 精英/Boss、秘密区 |
| 传奇 | 橙 | 2 + 1 固定传奇特效 | +20% | Boss、秘密区、原型武器 |

- **稀有度本身只加伤害基准与词缀数**，不直接改开火延迟/耗弹（保持手感与弹药经济稳定）；射速/耗弹变化走词缀。
- **词缀初例**（数值区间为初值）：伤害 +8~15% / 射速 +5~10% / 耗弹 -10~20% / 溅射范围 +15~30% / 穿透 +1 / 击退 +20~40% / 暴击率 +5~10%（暴击 ×2）/ 元素附加（灼烧/感电/冰冻，反应待设计）。
- **传奇特效初例**（待扩充）：「双生」每第 3 次开火免费复制一发；「战争机器」连续开火伤害 +5%/层（上限 5 层，停火 2s 清零）。
- **掉落稀有度权重（初值）**：敌人按等级掉落表（§4.7：普通敌人用该级权重，精英 = 等级 +1，Boss 按 Lv5）；武器箱 绿40/蓝40/紫18/橙2；秘密区 蓝30/紫50/橙20；商店 白50/绿40/蓝10。
- **合成升阶**（落地 §4.6 初案，初值）：3 把同级同弹药类型武器 + 零件 → 1 把高一级（词缀重随机）；传奇不可合成。
- **拆解零件量按稀有度**（初值）：白1 / 绿2 / 蓝4 / 紫8 / 橙16。
- 基础炮塔**无稀有度**（保底配发，不掉落不入库）；掉落物稀有度光效颜色 = 上表颜色（§4.1）。
- **【待设计】**：词缀池扩充与数值平衡、传奇特效清单、元素反应、重铸规则（随零件方案拍板）。

### 4.3 破坏 / 采集 / 探索
- **每种可破坏物都有生命值，生命值为 0 即被破坏**；伤害按武器伤害结算（见 §4.2），特殊免疫规则按对象配置。

**可破坏物清单（初版 6 型，生命值为初值待调）**：

| 可破坏物 | 生命值 | 破坏效果 | 备注 |
|---|---|---|---|
| 砖块墙 | 100 | 开通道/捷径 | 基础地形障碍 |
| 铁丝网 | 60 | 开通道 | **免疫机枪弹药武器**，只能被其他武器（炮弹/能量等）摧毁 |
| 哨戒炮 | 80 | 停止射击，解除区域火力 | 敌方设施，可优先摧毁减压 |
| 油桶 | 30 | 连锁爆炸（范围伤害） | 爆炸可引爆附近其他可破坏物 |
| 秘密墙 | 150 | 揭开隐藏区域/奖励 | 与普通墙壁**不同贴图**，肉眼可辨识 |
| 保险箱 | 120 | 掉金币，**也可能为空** | 金币概率/数量待设计 |

- **采集/战利品节点**（不在可破坏物表内）：矿脉（掉零件，见 §4.6）、武器箱（战利品，见 §5.1）。
- 战争迷雾随探索揭开；采集产出以零件为主，接入统一经济（§4.6）。
- **【待设计】**：保险箱金币概率/数量、迷雾规则、矿脉/秘密分布、破坏特效与反馈。

### 4.4 基地防守 / 建造
- 部分关卡/区域需守基地或发电机抗波次；可建炮塔与防御工事（消耗**建筑弹药**，见 §4.5）。
- 基地被毁 = 失败（或次目标扣分）；提供防守压力与建造策略。
- **【待设计】**：基地结构、建造槽、炮塔类型、波次进攻规则。

### 4.5 弹药 / 装填 / 过热
- **弹药按大类划分，不为每种武器单设弹种**：同类武器共享同一份弹药储备，避免弹药种类无限膨胀。
- **弹药容量由底盘决定**：每种底盘的各类弹药储备上限不同（见 §4.8）。
- **基础炮塔不耗弹**（基础机枪炮塔 / 基础炮塔，见 §5.3），保证任何构筑都有保底输出，不会打到弹尽罚站。
- 弹药有限，需采集/缴获/购买补充；装填/过热做成有节奏的技巧机制。
- 武器栏携带位有限，武器取舍即战术。

**弹药分类（4 类定稿 + 2 类备选，宁少勿多）**：

| 弹药 | 适用武器 | 说明 |
|---|---|---|
| 机枪子弹 | 机枪 / 速射炮 / 加特林 | 高射速低单发，最通用的消耗品 |
| 普通炮弹 | 火炮 / 霰弹炮 / 榴弹炮 | 低射速高单发，溅射/破墙主力 |
| 能量弹药 | 激光 / 电浆 / 闪电等能量系 | 统一「电池」口径，元素差异走武器词缀不另设弹种 |
| 建筑弹药 | 建造器 / 布雷器 | 放置障碍物、防御工事、防守炮塔时消耗（见 §4.4） |
| 导弹弹药（备选） | 追踪火箭 / 导弹巢 | 导弹系武器成规模后再独立，否则并入普通炮弹 |
| 重型弹药（备选） | 轨道炮 / 攻城炮 | 重炮系自成一派后再拆分，否则并入普通炮弹 |

- **弹药来源**：准备室补满/购买（金币）、关卡内弹药拾取、**敌人掉落弹药箱**（§4.1）、**粉碎缴获炮塔**（§4.1）。
- **【待设计】**：弹药拾取增量、价格、装填/过热曲线、武器栏装载预算。

### 4.6 成长与经济
- **局内**：升级三选一（词条/性能/模块）。
- **波间/关间**：商店买卖（金币）+ 同级武器合成升阶（零件）+ 改装载具。
- **局外**：永久解锁底盘/武器/天赋/模块（底盘升级/解锁见 §4.8）；挑战等级/星级换奖励；三模式共享。

**双货币体系（已定）**：

| 货币 | 定位 | 主要来源 | 主要用途 |
|---|---|---|---|
| 金币 | 通用货币 | 击杀奖励、目标完成、关卡结算、挑战星级奖励 | 底盘解锁/升级（已定）、出生点商店购买（§5.3）、支援技能解锁、弹药/补给购买（初值） |
| 零件 | 工业材料 | 拆解多余武器、矿脉采集（§4.3）、精英/Boss 缴获、秘密区 | 同级武器合成升阶、模块制作/升级、词缀重铸（初案，待拍板） |

- **拆解**：缴获的多余武器可在武器库拆解为零件——零件的天然来源，同时解决仓库膨胀。
- 零件用途为初案（「制作/重铸」方向），待拍板；金币/零件账户三模式共享（§3.4）。
- **【待设计】**：价格表、掉落/结算数量、解锁树（含挑战星级前置）、难度系数、天赋系统。

**最小 AI（v0.1 实现口径）**：

- **状态机**：`Idle/Patrol → Alert → Chase → Attack → Reposition → Dead`；爬行者用 `Chase → Explode → Dead`，固定炮塔无移动状态（§6.6 节点式状态机）。
- **感知**：距离 + 视线（对 wall 做 `RayCast2D`）；受击立即进入 Alert；枪声会惊动 400px 内的同类；脱离视线 5s 后回到 Idle。
- **移动**：v0.1 单区域用「直线追击 + 撞墙滑动」即可；多区域关卡接入分区流场（§7），AI 接口不变（只向移动层要方向）。
- **攻击**：有视线且进入射程才开火；炮塔按 180–240°/s 转向目标；v0.1 不做提前量预判，靠弹速与走位产生博弈。
- **走位**：远程敌人维持各自舒适距离（见上表），过近则后退/横移；被击退时暂停开火 0.5s。
- **死亡**：按 §4.1 掉落携械/弹药箱，释放占位格，触发击杀信号（成就/计分/掉落）。
- **性能**：索敌与路径目标每 0.2s 刷新一次，不每帧全量搜索；大量敌人走对象池（§7.2）。

**敌人等级（只规定掉落档位，初值）**：

- 每种敌人配置等级字段 `level`（Lv1–Lv5）：**只决定掉落炮塔的稀有度权重与允许出现的位置**，不改敌人行为与战斗数值（数值仍由敌人表 + 精英倍率决定）；同种敌人可按区域配不同等级。
- 掉落权重按等级（初值）：

| 等级 | 掉落稀有度权重 | 故事模式出现范围（初值） |
|---|---|---|
| Lv1 | 白80 / 绿20 | 第 1–2 章 |
| Lv2 | 白40 / 绿50 / 蓝10 | 第 2–4 章 |
| Lv3 | 绿30 / 蓝55 / 紫15 | 第 3–5 章 |
| Lv4 | 蓝40 / 紫50 / 橙10 | 第 5–6 章 |
| Lv5 | 紫60 / 橙40 | 第 7 章 / 秘密区 |

- **区域限制**：高等级敌人只出现在配置允许的位置——故事模式按章节递进（上表）；挑战模式按区域配置 `enemy_level` 范围（§5.6，外围低、核心高，秘密区可破格 +1 级），挑战规则可再整体 +1 级（§5.10）；割草模式随波次提升（初值每 5 波 +1 级，曲线待设计）。
- **精英** = 基础敌人等级 +1 的掉落表（不超过 Lv5）；**Boss** 固定按 Lv5 表。
- 监视器敌情页签显示敌人等级与掉落档位（§5.2），玩家可据此规划「去哪刷高级炮塔」。

**精英 / 设施 / Boss**：

- **精英**：基础敌人的换色强化变体（初值生命 ×3、伤害 ×1.5），必掉武器，掉落按等级 +1 表（§4.7 敌人等级）；同模换色派生阵营（§6.2）。
- **固定设施**：哨戒炮（固定火力点，见 §4.3）、生成器（持续刷爬行者/机枪吉普，摧毁停刷）。
- **Boss**：**待定**。
- **【待设计】**：其余敌人补数值、其余敌人 AI 行为细则、警戒/增援规则、Boss 机制。

### 4.8 载具基础属性与底盘设计

**基础属性（先定 5 项，后续按需扩展）**：

| 属性 | 口径 | 基准值（标准底盘） |
|---|---|---|
| 移速 | 车体移动速度，基准=100（引擎内按手感标定） | 100 |
| 生命值 | 车体 HP，归零即被击毁 | 100 |
| 防御力 | 减伤率 = 防御 / (防御 + 100)，初值公式 | 10（约 9% 减伤） |
| 视野 | 战争迷雾揭开半径，基准=100% | 100% |
| 炮塔转动速度 | 炮塔追瞄的转速；玩家给目标方向，炮塔按转速转过去 | 180°/s |

- **炮塔转速是「坦克感」的核心**：重型底盘转得慢，开火需要提前量与走位配合，而不是输入限制。
- **最终值口径**：底盘基础值 × (1 + 升级成长) + 模块/支援技能加成（如超级雷达 +50% 视野作用于最终视野）。

**世界尺度、相机与移动（已定 / 初版）**：

- **世界尺度**：1 世界单位 = 1 屏幕像素；基准分辨率 1920×1080（§6.3），玩家/敌人 64×64px，寻路格 32px。**相机默认 `zoom = (1, 1)`，不做动态缩放**（不随移速、瞄准、战斗强度变焦）；后续若需要缩放只作为设置项，不进入战斗数值。
- **相机行为**：`Camera2D` 挂在玩家载具上；位置平滑跟随（初值 8.0）；向鼠标瞄准方向做 **20% 屏幕前瞻**（look-ahead），让准星一侧多露出战场；**限制在关卡边界内**（不露出地图外）；旋转固定 0°。
- **震屏**：只改相机 offset，不改 zoom；开火 1px、受击 2px、爆炸 4–6px，0.15–0.3s 指数衰减；可在设置关闭。
- **移动手感**：WASD 为屏幕方向（上=屏幕上方），输入向量归一化；目标速度 = 方向 × `移速属性 × 2.2 px/s`（标准底盘 100 → 220 px/s）。加速 1600 px/s²、松键减速 2200 px/s²（约 0.12s 到满速 / 0.10s 停下），不做漂移。
- **车体朝向**：车体转向移动方向（540°/s）；静止时保持最后朝向。**炮塔独立追瞄**（炮塔转速见上表），因此可以「车体横移 + 炮塔侧射」。
- **碰撞体**：玩家用 `CharacterBody2D` + 圆形碰撞体，**半径 24px**（直径 48px，小于 64px 贴图，留出视觉余量）；与 wall / destructible / enemy 硬碰撞，**不与 projectile / pickup / fog 物理碰撞**（后三者用 Area2D 检测）。
- **受击判定**：不做全局无敌帧；接触伤害按「每个伤害源 0.5s 冷却」结算；单次爆炸对同一目标只结算一次。
- **单炮塔位**：炮塔枢轴在车体中心，炮口沿炮塔朝向前移 40px 生成子弹（底盘/武器可在数据表覆写炮口偏移）；车体只渲染 1 座炮塔，切换武器即换装（§5.3）。

**底盘清单（初版 8 型，数值为初值待调）**：

| 底盘 | 移速 | 生命 | 防御 | 视野 | 炮塔转速 | 武器栏 | 特性备注 |
|---|---|---|---|---|---|---|---|
| 标准 | 100 | 100 | 10 | 100% | 180°/s | 3 | 均衡新手，无特性 |
| 侦察 | 130 | 75 | 5 | 120% | 240°/s | 2 | 快、脆、看得远 |
| 重型 | 75 | 160 | 30 | 90% | 90°/s | 3 | 慢、硬、炮塔转速慢 |
| 突击 | 105 | 90 | 10 | 100% | 220°/s | 3 | 武器伤害 +15%（待接入武器系统） |
| 工程 | 95 | 110 | 15 | 100% | 150°/s | 3 | 建造/维修速度 +50%（待接入建造系统） |

**底盘成长（武器库）**：

## 5. 关卡设计（多区域挑战地图）—— 详细设计

> 适用范围：**故事模式 / 挑战模式**，地图均为**提前手工设计**。割草模式为程序生成战场，仅复用「炮塔 / 底盘 / 支援技能」装载系统，装载限制差异见 §5.7。

### 5.1 关卡总体结构

每关 = **准备室（出生点）+ 若干区域 + 最终区域**：

- **区域划分**：每关 3–6 个区域（含最终区域），各有主题、敌人配置、目标点、武器箱、资源点。
- **最终区域 Boss 可配置**：最终区域有没有 Boss 是**关卡配置项**（`final_area.has_boss` + `boss_id`），不与关卡硬编码绑定。
  - 有 Boss：最终区域为 Boss 战场（封闭/半封闭竞技场 + 可破坏掩体 + 增援入口），击败 Boss 结算。
  - 无 Boss：最终区域承载终局目标（摧毁母巢 / 夺取原型 / 防守撤离等），完成即结算。
  - 故事模式关键章节默认配置 Boss；挑战模式按关卡自由配置，同一地图可做「有 Boss / 无 Boss」变体提高重玩。
- **连接与捷径**：区域间主通道 + 可破坏捷径 + 秘密路径；鼓励探索与路线规划。
- **目标点**：主目标（必做）+ 次目标/可选区域（额外奖励）；基地/撤离点作为防守/提取目标。
- **战利品分布**：敌人携械 + 武器箱 + 秘密区稀有掉落，驱动探索。
- **警戒与增援**：区域警戒等级随战斗上升，触发增援；潜行/强攻产生不同节奏。

### 5.2 准备室（玩家出生点）

玩家出生在一个**小房间**（整备舱/车库），是关卡的安全区与装载决策点：

- **安全区**：敌人不进入、不受伤害；出闸门后开始关卡流程。
- **交互方式**：驾驶载具靠近设备 + 交互键（E）打开对应界面；设备在场景里预置为固定节点。

**核心设施（已定）**：

| 设施 | 功能 |
|---|---|
| 武器库 | 选择/装配武器，**最多 3 把（1 基础保底 + 2 缴获，受底盘格数限制）**；存取/拆解规则见 §5.3（库存上限 6，基础炮塔不入库） |
| 商店 | 随机出售炮塔（金币），每次进入准备室刷新（初值 4 格，见 §5.3）；购得后可直接装配或入库 |
| 监视器 | 查看本关情报，分两个页签：**挑战**（主/次目标、挑战规则/突变、完成条件、区域情报、装载限制）；**敌情**（本关出现的敌人种类、等级与掉落档位、携带炮塔、行为与弱点提示，数据来自 §4.7） |
| 图鉴终端 | 全游戏内容数据库：已解锁武器的完整详情 + 敌人/底盘/支援技能/成就/可破坏物/弹药等全部可查询内容（见下方口径） |
| 底盘位 | 选择/更换底盘（1 台）；底盘用金币升级/解锁（见 §4.8） |
| 支援技能终端 | 装配支援技能，**最多 3 个**（故事/挑战模式；挑战规则可禁用） |
| 补给维修位 | 弹药补满 + 车体维修（§5.9 口径：准备室为完整补给点）；可花金币额外购买弹药（初值） |
| 出击闸门 | 确认装载后出发 |

- **监视器 = 夺械导航**：敌情页签让玩家「想要某武器 → 查哪种敌人携带 → 去对应区域刷」，把刷装备从盲刷变成有目标的狩猎；未探索区域的敌人情报可配置为隐藏（显示「???」，初值：进入过该区域后解锁）。
- **图鉴终端口径**：
  - **内容全覆盖**：武器（开火延迟/伤害/耗弹/弹道特性/稀有度与词缀说明）、敌人（等级/携械/行为弱点）、底盘、支援技能、成就、可破坏物、弹药——整个游戏的可查询内容都在这一个设备上实现。
  - **解锁规则**：武器首次获得（缴获/购买/开箱）即解锁完整详情；未解锁显示剪影 + 获取途径提示（哪种敌人携带/哪类区域产出）；敌人首次遭遇解锁；成就按达成进度显示。
  - **数据同源**：图鉴直接读 `data/` 静态配置表，与实战数值同一份数据，不维护第二份数值文案（改数值图鉴自动跟上）。
  - **与监视器分工**：监视器 = 本关上下文（本关目标/挑战规则/本关敌情）；图鉴终端 = 跨关卡永久数据库（解锁进度三模式共享，§3.4）。
- **候选设施（初案，待拍板）**：

| 设施 | 功能 | 备注 |
|---|---|---|
| 改装台 | 同级武器合成升阶、词缀重铸（消耗零件） | §4.6 零件用途的落地设备，随零件方案一起拍板 |
| 试射靶场 | 房间内小块靶区，试射已装配武器验证构筑手感 | 试射不耗弹（初值）；也可用来打靶测试新缴获武器 |

- **中途返回**：可通过通道返回准备室补给/换装（每关可配置是否允许；故事模式可锁定为单程）。
- **设施按关卡配置**：`spawn_room` 可禁用部分设施（如故事模式某关禁用商店，强制用配发武器解题，见 §5.6）。

### 5.3 武器栏与单炮塔（最多携带 3 把）

**挂载与开火口径（已定）**：

- 车体只有 **1 个炮塔挂载位**：同一时刻只挂载、只开火 **1 把武器**；视觉上只有 1 座炮塔。
- **武器栏 3 格 = 1 个保底格 + 2 个缴获格**（底盘格数不同时按 §4.8：2 格 = 1 基础 + 1 缴获）：
  - **保底格**：常驻 1 座基础炮塔（基础机枪炮塔 / 基础炮塔二选一，准备室可换），不耗弹、不入库、不可粉碎，保证任何构筑都有输出。
  - **缴获格**：放缴获/商店购买的耗弹武器，最多 2 把。
- **切换**：数字键 1/2/3（手柄肩键/十字键）切换当前武器；换装 0.3s，期间不能开火，不消耗弹药；切换不改变各武器自身状态。
- **空弹**：开火时发现当前武器弹药不足 → 自动切到下一把有弹武器；若缴获格都无弹 → 切回保底格基础炮塔。手动仍可切到空弹武器，HUD 标红、开火无效。
- **拾取替换**：武器栏缴获格已满时拾取，选择替换其中 1 把，旧武器丢在原地；**保底格不可被替换**。
- 武器受重量/能量预算约束（见 §4.1），缴获武器可直接顶替；弹药按大类共享储备（见 §4.5）。
- **为什么保留保底格**：把「不弹尽卡死」从口头承诺变成结构保证——无论怎么配装，永远有一把不耗弹武器可切；代价是缴获武器最多 2 把，用构筑上限换稳定底线（实测后可再放宽）。

**初始炮塔（不耗弹，永久可用，不入库）**：

| 炮塔 | 定位 | 开火延迟 | 伤害 | 耗弹/次 |
|---|---|---|---|---|
| 基础机枪炮塔 | 高射速清杂兵，保底输出 | 0.125s | 6 | 0 |
| 基础炮塔 | 低射速高单发 + 小范围溅射 | 1.2s | 30 | 0 |

**武器库与持有规则（已定）**：

- 武器库最多保存 **6 把缴获武器**；基础炮塔不入库（初始配发，随时可用）。
- 从武器库选择装配 → 武器**离开武器库**装入武器栏；**身上武器通关后或被击败都不消失**，默认随玩家保留。
- 回准备室时可将身上武器存回武器库；武器库已满时选择拆解为零件（见 §4.6）或替换。
- 缴获炮塔装配后同样随玩家保留（不再要求撤离提取）；武器库三模式共享（见 §3.4）。

**获取途径分层**：

| 途径 | 范围 |
|---|---|
| 初始配发 | 基础机枪炮塔、基础炮塔（不耗弹） |
| 出生点商店 | **随机出售**一些武器炮塔，金币购买；每次进入准备室刷新（初值 4 格），购得后直接装配或入库 |
| 关卡获取（主要） | 绝大多数武器只能从敌人缴获、隐藏房间、武器箱获得 |

- 武器清单与数值口径见 §4.2；弹药补给见 §4.5。

### 5.4 底盘选择

- 载具基础属性（移速/生命/防御/视野/炮塔转速）、8 型底盘清单与武器库升级/解锁规则见 **§4.8**。
- 准备室提供底盘位，出击前选择 1 台；故事模式按关卡限制可用底盘（见 §5.7）。

### 5.5 支援技能（故事/挑战最多 3 个）

支援技能分**被动**（装配即生效）与**主动**（按键释放，有冷却/能耗）；上限 3 个，主动/被动可混装。

**已定技能**：

| 技能 | 类型 | 效果 |
|---|---|---|
| 反应装甲 | 被动 | 受到的所有伤害 **-50%** |
| 超级雷达 | 被动 | 视野 **+50%**，战争迷雾快速清除（揭开速度 ×2，初值） |
| 无人机支持 | 主动 | 释放 1 架攻击无人机，跟随玩家自动索敌；持续 30s / 冷却 60s（初值） |
| 自动修复 | 被动 | 未受击 5s 后自动回血，每秒恢复 2% 最大生命（初值） |
| 反地雷 | 被动 | 无视地雷：地雷不触发、免疫地雷伤害 |
| 绝境防爆 | 被动 | 生命低于 30% 时**免疫爆炸伤害**（油桶/爬行者自爆/地雷/爆炸系溅射等）；血量抬回 30% 以上即失效，实时判定 |

- 绝境防爆口径：只免疫**爆炸来源**伤害，子弹/炮弹直击照常；结算层需给伤害标记来源类型（爆炸/直击），实现时接入统一 `hit()` 结算。与反应装甲叠加时免疫优先（0 伤害不再走减伤）；与自动修复配合形成「低血防爆 → 脱战回血」的逃生循环。

**候选扩充技能**（初值待调，按版本逐步实装）：

| 技能 | 类型 | 效果 |
|---|---|---|
| 应急护盾 | 被动 | 生命首次低于 30% 时获得护盾（吸收 30% 最大生命，每局限 1 次） |
| EMP 脉冲 | 主动 | 范围瘫痪机械敌人 3s，冷却 45s |
| 炮火支援 | 主动 | 标记区域呼叫轰炸，冷却 90s（HELLDIVERS 式战略配备） |
| 过载 | 主动 | 8s 内射速 +50%，过热积累 +50%，冷却 40s |
| 烟雾掩护 | 主动 | 释放烟幕阻断敌方锁定/仇恨 5s，冷却 30s |
| 磁力收集 | 被动 | 拾取范围 +100%，掉落物自动吸附 |
| 弹药回收 | 被动 | 击杀时 25% 概率返还弹药，弹药上限 +20% |
| 诱饵投影 | 主动 | 投放吸引火力的全息诱饵，持续 8s，冷却 35s |
| 氮气加速 | 主动 | 3s 内移速 +80%，冷却 20s |

- 支援技能局外解锁、三模式共享（见 §3.4）。
- 平衡备注：反应装甲（常驻 50% 减伤）价值极高，实测后可用解锁门槛/稀有度调节，不改变其效果口径。
- **【待设计】**：技能完整数值、冷却/能耗表、解锁树。

### 5.6 区域模板与关卡配置（数据驱动）

- **区域模板**（手工地图的设计单元）：废墟区 / 工业区 / 矿区 / 基地核心区 / Boss 竞技场等；每模板定义敌人生成表、目标点插槽、武器箱/资源点密度、可破坏物分布。
- **关卡配置字段**：

| 字段 | 说明 |
|---|---|
| `areas[]` | 区域列表（模板 + 敌人配置 + `enemy_level` 等级范围 + 目标 + 战利品） |
| `spawn_room` | 准备室布局与可用设施（可按关卡禁用商店/改装台等，见 §5.2） |
| `final_area.has_boss` / `boss_id` | 最终区域是否有 Boss 及 Boss 型号 |
| `objectives` | 主/次目标组合（歼灭/夺取/防守/采集/撤离） |
| `loadout_rules` | 装载限制：可用武器/底盘/技能池与数量上限（按模式覆写） |
| `challenge_rules` | 挑战规则（仅挑战模式读取）：装载锁定 / 时限 / 突变因子 / 挑战等级 / 评分倍率（§5.10） |
| `unlock` | 解锁条件：故事章节 / 前置挑战星级 / 成就（挑战关卡用） |
| `revisit_spawn` | 是否允许中途返回准备室 |

**地图场景结构（Godot 场景优先，已定）**：

> 原则：**几何与摆位在场景里，规则与数值在 JSON 里**。同一张 `.tscn` 可配多份关卡配置（故事/挑战/变体），不复制地图。

```text
level_<id>.tscn (Node2D + level.gd)
├─ Ground        TileMapLayer，只放背景/地表装饰，无碰撞
├─ Walls         Node2D 容器（墙体实例，不用 TileMapLayer）
│   └─ Wall_<id>  wall_base.tscn 实例：StaticBody2D（层 1）+ 碰撞 + 静态/动画视觉
├─ Props         Node2D，可选：无碰撞装饰/动画道具
├─ Regions       Node2D
│   └─ Region_<id>  Area2D + CollisionPolygon2D（监测 player 层）
│                   metadata: region_id / enemy_level_min / enemy_level_max
├─ Spawns        Node2D（Marker2D，按入组区分）
│   ├─ spawn_player / enemy_spawn / elite_spawn / destructible
│   └─ weapon_crate / resource_node / objective_point / extraction
├─ CameraBounds  Marker2D × 4 或 ReferenceRect，相机钳制范围
└─ Entities      运行时容器（敌人/子弹/掉落物/特效）
```

- **区域**：`Area2D` 只做区域检测（进出信号、当前区域名、警戒范围），不参与物理阻挡；区域数据（等级/生成表/目标）以 `region_id` 关联 JSON。
- **标记点**：全部用 `Marker2D` + 分组，关卡 JSON 只引用标记名（`player_spawn: "spawn_player_a"`），不写死坐标。
- **背景**：`Ground` 的动画只用 `TileSet` 动画瓦片（水/岩浆/屏幕等），不参与碰撞；需要独立动画、交互或遮挡关系的装饰放 `Props`。
- **墙体（已定）**：`Ground` 只负责背景；墙体**不用 `TileMapLayer`**，而是 `wall_base.tscn` 场景实例。理由：动画墙/门/能量屏障、可开关墙都要逐实例控制动画与碰撞，`TileMapLayer` 只能整层控制，做不了单段开合。
  - `wall_base.tscn` = `StaticBody2D`（层 1）+ `CollisionShape2D` + `Sprite2D` 或 `AnimatedSprite2D` + 可选 `AnimationPlayer`；导出 `wall_kind`、`footprint_cells`、`initially_open`。
  - 静态墙、动画门、能量屏障共用同一基类场景，差异走导出参数/子场景；长墙按 64/128px 墙段拼接；纯静态长墙可用一个 `StaticBody2D` 挂多个 `CollisionShape2D` 合并碰撞，动画/开关墙保持逐段独立节点。
  - 开合墙对外只暴露 `set_open(bool)`：内部播动画、用 `set_deferred("disabled", ...)` 切换碰撞、调用 `LevelGrid.set_cells_blocked(footprint_cells, blocked)` 同步流场/占位，并标脏所在区域；动画轨道不直接改 `disabled`。
  - 墙体不写进关卡 JSON；JSON 只引用 `region_id`/marker，不写墙坐标。可破坏的砖墙/秘密墙仍走 `destructible_base.tscn`（§4.3），不混入 `wall_base`。
  - 性能：v0.1 单关墙体节点控制在数百段内；静态重复墙后续可换 `MultiMeshInstance2D` 合批（碰撞仍按段/合并体），动画墙独立。
- **地图尺寸（初值）**：单区域约 1024×768px，3 区域 + 通道总量 ≤4096×3072px；相机按 `CameraBounds` 钳制（§4.8）。
- **可破坏物**：作为场景实例摆放（`destructible_base.tscn` 子场景），摧毁后释放占位格并通知所在区域流场标脏（§7）。
- **寻路数据**：由 `Walls` 实例的 `footprint_cells`（未填则按碰撞体 AABB 以 32px 栅格化）+ 可破坏物占位在运行时构建；不预烘焙导航网格。墙体开关/摧毁时增量更新对应格子并标脏区域流场，保证「炸墙开捷径」即时生效。

### 5.7 模式装载规则对比

| 项 | 故事模式 | 挑战模式 | 割草模式 |
|---|---|---|---|
| 武器 | ≤3（1 基础保底 + 2 缴获，受底盘格数限制），关卡发放/限定武器池 | ≤3（1 基础 + 2 缴获），默认武器库自由选，可被挑战规则锁定 | 初始 3，局内升级可扩（初值上限 6） |
| 底盘 | 关卡指定或限定范围 | 武器库自由选，可被挑战规则锁定 | 自由选 |
| 支援技能 | ≤3，仅已解锁 | ≤3，武器库自由选，可被挑战规则禁用 | **无数量限制** |
| 地图 | 手工（线性目标） | 手工（自由探索 + 挑战规则） | 程序生成 |
| 挑战规则 | — | 装载/时限/突变/评分倍率（§5.10） | — |

- 故事模式的限制服务叙事节奏（如「本关仅配发侦察底盘 + 1 基础 + 1 缴获武器」），制造受限关卡的解题乐趣。
- 挑战模式的限制来自**规则**而非叙事，目的是制造打法差异与可比较的分数；同一地图可配置多套规则。
- 割草模式放开限制，配合局内三选一成长做无上限构筑的爽感。

### 5.8 示例关卡：矿区突袭（挑战模式模板）

准备室 → A 废墟哨站（歼灭哨戒炮）→ B 矿区主道（可选：采集 X 资源）→ C 精炼厂（夺取原型武器）→ 最终区域 D 基地核心（`has_boss=true`：Boss「重型压路者」；可配置为无 Boss 的「摧毁母巢」变体）。

- 捷径：B→D 炸开矿道暗门；秘密区：A 区炸墙藏稀有武器箱。
- 挑战规则示例（挑战等级 III）：装载锁定「仅基础炮塔 + 1 把缴获武器」；限时 12 分钟；突变「高压警戒 + 精英猎场」；3 星 = 12 分钟内通关 + 全部次目标 + 受击低于阈值。
- 同一张地图通过替换规则产出变体：无 Boss 采集撤离、限时夺取、禁商店挑战等。

### 5.9 失败 / 补给 / 评分（补充）

- **失败**：载具被击毁 → 回准备室重组/读检查点；**身上武器不消失**（见 §5.3），未拾取的地面掉落物留在关卡。
- **补给**：准备室为完整补给点（弹药补满/维修）；野外靠缴获、采集与补给箱。
- **评分**：通关时间 + 受击量 + 次目标完成度 + 收集度 → 三星评分 + 排行榜（故事/挑战共用基础分；挑战模式再乘挑战等级与突变倍率，见 §5.10）。
- **生成方式**：故事/挑战=手工地图；割草=程序生成。
- **【待设计】**：区域模板库、目标/战利品配置工具、评分细则。

### 5.10 挑战规则与突变因子

> 挑战模式的核心差异层：目标决定「做什么」，挑战规则决定「怎么做、值多少分」。规则与目标解耦，同一张地图换规则即可反复产出挑战关。

**设计原则**：

- **改变打法，不只加血**：每条规则都要迫使玩家换武器/路线/节奏；纯数值加厚只作为最低难度档。
- **可叠加、有反制**：突变因子之间尽量正交，且都能用现有系统（雷达/EMP/烟雾/基础炮塔/破坏捷径）应对。
- **信息透明**：出击前在准备室监视器与挑战选择界面完整展示本关规则/突变/星级阈值，不做隐藏惩罚。
- **分数可比较**：评分公式与倍率固定；排行榜只比较同关卡、同挑战等级、同规则组合的成绩。

**规则分类（初版）**：

| 类别 | 规则 | 示例 |
|---|---|---|
| 装载 | 底盘/武器池/槽位/设施限制 | 仅基础炮塔；≤2 炮塔；禁用支援技能；禁用商店 |
| 时限 | 总时限 / 目标限时 / 撤离窗口 | 12 分钟通关；夺取目标 4 分钟内完成 |
| 突变 | 敌人/环境/资源修正 | 见下方突变因子表 |
| 环境 | 视野/地形/天气 | 迷雾不散；可破坏物减半；捷径封闭 |
| 评分 | 倍率与额外条件 | 无伤加成；全次目标加成；限时加成 |

**突变因子（初版 8 个，数值待调）**：

| 突变 | 效果（初值） | 反制/提示 |
|---|---|---|
| 高压警戒 | 警戒增援触发更快，单波数量 +50% | 速战速决、EMP/烟雾脱战 |
| 精英猎场 | 精英出现比例翻倍 | 优先夺械、爆发秒杀 |
| 弹药紧缺 | 弹药掉落 -50%，补给箱减少 | 基础炮塔保底、采集换弹药 |
| 迷雾锁区 | 迷雾不自动揭开，需雷达/探索 | 超级雷达、无人机侦察 |
| 硬壳 | 敌人护甲 +30% | 高单发/穿甲武器 |
| 蜂群 | 敌人数量 +50%，单体生命 -20% | 溅射、油桶连锁 |
| 限时风暴 | 关卡总时限 -30% | 路线规划、炸捷径 |
| Boss 突袭 | Boss 提前入场或最终区域双 Boss（初案） | 预留爆发、基地工事 |

**挑战等级（初版）**：

| 等级 | 规则包 | 分数倍率 | 掉落加成 |
|---|---|---|---|
| I | 无突变 | ×1.0 | 基础 |
| II | 1 个突变 | ×1.2 | +10% |
| III | 2 个突变 | ×1.5 | +20% |
| IV | 3 个突变 + 限时 | ×2.0 | +35% |
| V | 4 个突变 + 装载锁定 | ×3.0 | +50% |

- 等级解锁：完成同关上一等级后开放下一等级（初版）；V 级另需该关 3 星（初值待调）。
- 数值缩放：敌人等级/生命/伤害随挑战等级提升；Boss 生命按挑战等级倍率缩放（曲线待设计），避免终局武器让复用故事地图的 Boss 变成木桩。
- 每日/每周挑战：固定关卡 + 固定规则/突变 + 固定种子，全球同题、独立排行榜；每周轮换（初版，具体周期待调）。

**评分与星级（初值）**：

- 基础分 = 目标分 + 时间分 + 生存分（受击/剩余生命）+ 收集分（次目标/秘密/战利品）。
- 总分 = 基础分 × 挑战等级倍率 × 突变倍率；排行榜按总分排序。
- 星级阈值按关卡标定：1 星=通关；2 星=基础分达标准线；3 星=基础分达高线且完成全部次目标（具体数值随关卡配置）。
- **【待设计】**：完整突变池与数值、评分公式权重、星级阈值表、每日/每周种子与赛季规则、挑战专属掉落表。

### 5.11 目标系统与胜负判定（实现口径）

> 目标系统三模式共用：故事/挑战读关卡 JSON，割草由波次系统动态生成同结构目标；**只做一套 `ObjectiveManager`，不按模式分叉**。

**数据与运行结构**：

- 关卡 JSON 的 `objectives[]` 每项一条目标；运行时有 `ObjectiveManager` 节点统一持有、订阅 gameplay 信号、维护进度，不把判定散落在敌人/交互物脚本里。
- 目标字段：`id / type / primary / target / reward / optional`；运行态：`state`（inactive / active / completed / failed）、`progress`、`started_at`。
- **事件驱动**：只监听信号，不每帧轮询——
  - `enemyKilled(enemy, regionId, tags)`：歼灭计数。
  - `itemPicked(itemId)` / `interactableUsed(id)`：夺取/交互。
  - `regionEntered(regionId)`：区域/探索目标。
  - `destructibleDestroyed(id, regionId)`：摧毁目标/流场标脏。
  - `playerDamaged(amount)`：受击统计（评分/无伤条件）。
  - `levelTimerTick(secondsLeft)`：限时目标。

**v0.1 实装的目标类型**：

| 类型 | 判定 | 参数 | 完成条件 |
|---|---|---|---|
| `eliminate` 歼灭 | 指定区域内击杀计数 | `region`、`count`、可选 `enemy_tag` | 计数达到 `count` |
| `seize` 夺取 | 靠近目标点持续交互（初值 2s，受击打断）或拾取指定物品 | `marker` / `item_id`、`channel_s` | 交互完成/物品入手 |

- 后续扩展 `defend`（守护实体存活 N 波）、`collect`（资源量）、`extract`（带战利品到撤离点），字段结构不变。

**胜负口径**：

- **通关**：任一 `primary` 目标完成 → 触发 `levelCleared` → 结算（次目标只加奖励/评分，不阻塞通关）。
- **失败**：玩家载具被击毁 → `levelFailed("player_destroyed")`；挑战规则限时归零 → `levelFailed("timeout")`；防守目标被毁（后续）→ `levelFailed("defense_lost")`。
- **只判定一次**：进入结算后锁定目标状态，后续击杀/交互不再计分；重开走 `Game.restartLevel()` 重建关卡。
- **可序列化**：`ObjectiveManager.getState()` 输出纯数据（id/state/progress），供存档、联机快照、结算复核。
- **HUD 同步**：主目标常驻、次目标折叠；目标完成/失败用 toast + 追踪列表打勾，不弹模态窗。

**v0.1 灰盒验证目标**：A 区「歼灭 12 个敌人」+ D 区「夺取原型武器」两条目标即可验证「主/次目标 + 通关/失败 + 重开」全链路。

## 6. 美术与音效方向

### 6.1 美术风格与管线（已定）

- **风格**：偏像素风、低多边形块面感；美术花费显著低于手绘逐帧像素动画。
- **管线**：**Blockbench 3D 建模**（低多边形/方块风格）→ **俯视角正交渲染（截图）输出** 2D 精灵/精灵表 → 游戏内用 Godot 2D 精灵渲染。
- 游戏本体仍是**俯视角 2D**，不做运行时 3D：无 3D 渲染开销，特效/粒子走引擎 2D 系统。
- **像素化处理**：低分辨率渲染 + 最近邻采样、有限调色板、硬边着色（无抗锯齿），全局统一像素密度。
- **量产优势**：同一模型换色即可派生敌人阵营/精英变体；新载具 = 新底盘模型 + 复用炮塔渲染流程。

### 6.2 换色方案

- 模型上预留**标记色区域**（如装甲主色 / 副色 / 阵营标记色），在 Blockbench 中用调色板与部件命名约定。
- 实现方式二选一（实测后定）：
  - **运行时 shader 换色**：把标记色替换为目标配色，一份资产支持任意颜色，实现坦克整体变色（队伍色/皮肤）；
  - **预烘焙变体**：渲染时直接输出多套配色，运行时零开销但资产量翻倍。
- 用途：玩家底盘皮肤/队伍色、敌人阵营识别（同模不同色 = 不同阵营）、受击闪白等反馈也可走换色。

### 6.3 渲染与动画规格（初值）

- **车体与炮塔分开渲染**，均预渲染多角度方向帧（**初值 16 方向**，正式在 16/32 间实测）；运行时按角度选帧；避免直接旋转低分辨率像素图产生抖动，也天然支持炮塔转动速度（见 §4.8）。
- **分辨率与基准尺寸（已定）**：游戏分辨率 **1920×1080（1080p）**；玩家与敌人基准尺寸均为 **64×64px**，全局统一像素密度。
- 动画需求少：开火后坐、履带滚动（可选）、爆炸/粒子用引擎特效。
- **v0.1 美术口径**：先用占位图/整体旋转验证玩法，不阻塞第一版；32 方向资产量翻倍，单兵开发优先 16 方向 + 炮塔独立旋转。

### 6.4 反馈与音频

- 反馈（Juice）：震屏、命中停顿、受击闪白、爆炸粒子、资源/武器掉落喷射；音画随战斗强度变化。
- 音频：分层音效（武器/爆炸/命中/采集/夺械）+ 动态 BGM。
- **【待设计】**：调色板与标记色规范、精灵分辨率/帧数规范、特效规范、音频清单。

## 7. 技术方案

- 引擎：Godot 4.x；GDScript 为主，性能热点（寻路/大量实体）可用 C#。
- 工程目录：`Project-Sidewinder/`（Godot 工程，**已初始化**）：`scenes/`（tanks/enemies/weapons/projectiles/level/objects/hud/fx/fsm）、`scripts/`（autoload/tank/enemies/weapons/level/objects/ui/fx/fsm）、`sprites/`、`shaders/`、`sounds/`、`fonts/`、`lang/`、`data/`（静态配置）。
- 编码规范：**`doc/CODE_GUIDELINES.md` 为唯一编码规范**（camelCase / 显式类型 / 场景优先 / 节点式状态机等，改编自 boxHead-remake）；手写与 AI 生成代码一律以它为准。
- 工程配置：Godot 4.7 GL Compatibility、**1920×1080（1080p）**、最近邻过滤（像素风，§6）；输入映射 WASD 移动 + 鼠标开火/瞄准 + 1/2/3 切换 + E 交互 + F 粉碎 + Esc 暂停（§4.10 完整表）；物理层命名 wall/player/enemy/projectile/destructible/pickup/fog（初值）。
- 架构：模块化系统（载具/武器/敌人/关卡/目标/经济/UI），信号 + 明确 API 协作；静态配置与运行时状态分离；**目标系统做成可组合模块以复用三模式**。
- 美术资产：Blockbench 预渲染精灵 + 换色 shader（见 §6）；运行时纯 2D 渲染。
- 适配：手柄 + Steam Deck；简中首发。

**局内流程与会话状态（`Game` Autoload，初版）**：

- **职责边界**：`Game` 只持有**会话状态与切场景**，不实现战斗逻辑；关卡场景自己拥有实体、目标与结算数据。
- **会话数据**：`mode`、`level_id`、`level_config`、`loadout`（底盘 id / 武器栏 3 格 / 支援技能 3 格）、`run_stats`（击杀/受击/用时/战利品）、`rng_seed`。
- **流程**：`Boot → 主菜单 → 模式选择 → 关卡选择 → 装载（v0.1 覆盖层）→ 关卡 → 结算 → 下一关/重试/返回`；切场景统一走 `Game.gotoScene(path)`。
- **装载延续**：关卡内拾取的武器进武器栏缴获格（满则选择替换）；通关/被击败都保留（§5.3）；回准备室可存回武器库。失败重开不丢武器。
- **信号**：`runStarted`、`levelLoaded`、`levelCleared(result)`、`levelFailed(reason)`、`runEnded`；HUD/成就/存档只监听，不反向依赖关卡节点。
- **暂停与重开**：`get_tree().paused = true` + 暂停菜单 `process_mode = ALWAYS`；`Game.restartLevel()` 用同一 `rng_seed` 与同一装载重建当前关卡。
- **随机统一入口**：所有玩法随机（掉落/词缀/增援）走 `Game.rng`（按 run/level 播种），便于复现、每日种子与联机同步。
- **结算载荷**：`{ level_id, cleared, time_s, kills, damage_taken, objectives[], loot[], score, stars }`，UI 与存档共用同一结构。

**物理层与碰撞矩阵（已定）**：

> 位值：wall=1、player=2、enemy=4、projectile=8、destructible=16、pickup=32、fog=64。改层前先查此表。

| 对象 | 层 | 节点类型 | 碰撞/检测 mask | 说明 |
|---|---:|---|---|---|
| 墙 / 边界（`wall_base` 实例） | 1 wall | StaticBody2D | 无 | 静态墙/动画门/能量屏障统一此层；关闭时挡玩家/敌人/子弹 |
| 玩家载具 | 2 player | CharacterBody2D | wall + enemy + destructible = **21** | 与敌人硬碰撞；不被动态占位阻挡（见下方避碰） |
| 敌人本体 | 4 enemy | CharacterBody2D | wall + player + destructible = **19** | **敌人之间不做物理碰撞**，防重叠走多格占位表 |
| 玩家子弹/炮弹 | 8 projectile | Area2D | wall + enemy + destructible = **21** | 每帧线段检测（§4.2）；不检测玩家/拾取物 |
| 敌方子弹/炮弹 | 8 projectile | Area2D | wall + player + destructible = **19** | 同上；不检测敌人（避免友伤穿透问题） |
| 可破坏物 | 16 destructible | StaticBody2D | 无 | 被子弹 mask 命中；摧毁后移除碰撞体 |
| 掉落物/拾取物 | 32 pickup | Area2D | player = **2** | `body_entered` 自动拾取或提示交互 |
| 战争迷雾 | 64 fog | Area2D | player = **2** | 只做区域揭开检测，不做物理阻挡 |

- **Area2D 口径**：子弹/拾取/迷雾用 `collision_mask` 检测目标层；被检测对象只需在对应 `collision_layer` 上。子弹同时需要 `monitoring = true`。
- **不与谁碰**：子弹不碰子弹/拾取物/迷雾；玩家不碰子弹/拾取物/迷雾；敌人不碰敌人/拾取物/迷雾。
- **可破坏物**：静态体，被摧毁后立即 `queue_free()` 并从流场/占位数据中移除（§7 寻路联动）。
- **墙体**：统一用 `wall_base.tscn` 实例（层 1）；开门/关门只切 `CollisionShape2D.disabled`（`set_deferred`）并同步 `LevelGrid` 占格，不重建节点。可破坏的砖墙/秘密墙仍走 `destructible_base.tscn`（层 16）。

**性能预算（初值，待实测）**：

- 目标 60 FPS / 1080p：单帧 16.6ms，其中玩法逻辑 ≤8ms、渲染 ≤6ms，余量留给 GC/系统。
- 同屏上限初值：敌人 300、飞行弹 500、掉落物 200、粒子 1000；超出按对象池回收/延迟生成。
- 刷新节拍：敌人索敌 0.2s、流场单区域按脏标记重算（每帧最多 1 个区域）、迷雾 0.1s；不做每帧全图寻路。
- 对象池：子弹、敌人、伤害数字、爆炸特效优先池化（§7.2）。

**敌人寻路：分区层级流场（已定）**：

- **问题**：多区域互通的大地图若整图格子化做单一流场，格子量过大；故采用「区域分块流场 + 区域间门户图」的层级方案。
- **区域内（流场）**：地图格子化保留，但按区域分块；流场**只在玩家所在区域 + 相邻区域**按需计算，敌人采样流场方向 O(1)，群怪性能与整图流场一致。格子尺寸初值 32px（按车体手感标定）。
- **区域间（门户图）**：区域间通道/门抽象为小图（节点 = 区域，边 = 通道，手工地图天然有边界，§5.1 每关 3–6 区域）；远处敌人先在门户图上 A* 走向玩家所在区域，沿通道点移动，进区后切换为流场跟随。
- **多目标**：流场按目标生成（玩家 / 基地 / 撤离点）；基地防守目标时敌方同时存在「攻玩家」与「攻基地」两张流场，按敌人配置选择。
- **墙体数据**：`Walls` 下的 `wall_base` 实例在 `_ready()` 向 `LevelGrid` 注册占格（优先用导出 `footprint_cells`，未填则由碰撞形状 AABB 栅格化）；门开合/墙体摧毁调用 `set_cells_blocked()` 增量更新并标脏，不重扫整图。
- **与破坏联动**：可破坏物被摧毁 / 常闭门被打开 → 所在区域流场标脏重算；炸开秘密墙/捷径开通新连接 → 门户图加边（破坏即探索在寻路层的落地）。
- **割草模式**：单竞技场程序生成、无分区，直接用整场流场；实现起点复用已有流场 demo（`F:\godotTestDemo\godot4flow-field`）。
- **【待设计】**：流场刷新频率与分帧预算、跨区过渡平滑、格子尺寸实测标定。

**动态避碰：多格占位表（已定，改造自 boxHead-remake）**：

- **分层口径**：流场给方向，占位表仲裁「这个方向能不能走」；静态障碍间隙由流场层保证，动态物体（敌人之间）防重叠由占位表保证。
- **占位表**：全局 `Dictionary[cellKey → Node]`（参考 boxHead-remake `MapData.reservedCells`），O(1) 查询；占用者引用失效时自动清理（`is_instance_valid`）。
- **多格登记**：车体 64px > 格子 32px，按**碰撞半径**把覆盖的格子整组登记/释放（boxHead 单格占位的改造点）；碰撞体小于贴图，碰撞半径初值 24px。
- **连续申请**：每帧移动前对「即将进入的格」申请占用；被占 → 该方向停止/滑动，沿流场次优方向绕行（不照搬 boxHead 离散移动的「站住干等」）；离开的格即时释放。
- **作用范围**：占位只对敌人生效；**玩家不被占位阻挡**（避免被围死），玩家与敌人的硬碰撞走物理层。
- **中断与死亡**：敌人死亡/状态切换/被击退时释放全部占格；击退位移同样走申请仲裁，撞到占位即停。
- **性能口径**：几百敌人 × 每车约 4 格的字典操作，每帧数千次 O(1) 查询，GDScript 可承受；比 RVO 避碰便宜且行为确定（利于 §10.1 联机状态同步）。
- **【待设计】**：碰撞半径实测标定、被堵时次优方向选择细则、占位与击退/冲撞的交互。

**存档系统（已定）**：

- **双文件分离**：

| 文件 | 内容 | 格式 |
|---|---|---|
| `settings.cfg` | 游戏配置：画面/音量/语言/按键 | ConfigFile（INI），人类可读可直接改 |
| `player.json` | 玩家数据：武器库（≤6）/底盘解锁与等级/金币零件/成就进度/图鉴解锁/章节进度/挑战星级与最佳分/累计统计 | JSON + `schemaVersion` 字段 |

- **读取路径口径**：编辑器运行 → `user://`；打包后 → **程序所在目录**（`OS.get_executable_path().get_base_dir()`，绿色便携，存档随程序走）；程序目录不可写时（如装在 Program Files）回退 `user://`（初值）。
- **加密口径：初版不加密 + 完整性校验**。理由：单机 PvE 为主，加密密码必然硬编码在客户端、可被提取，收益低；改为 JSON 内嵌 SHA-256 校验字段，防损坏/误改，校验失败回退备份。排行榜公平性留到联机期做服务端校验（§10.1）；后续若需要加密，Godot `FileAccess.open_encrypted_with_pass()`（AES-256）可直接升级，读取接口预留加密切换。
- **写入安全**：关键事件触发保存（通关结算/解锁/购买/装配变更）+ 退出时；先写临时文件再原子替换，保留上一份 `.bak`；启动时主文件校验失败 → 读 `.bak`。
- **版本迁移**：`schemaVersion` 不匹配时走迁移函数逐版升级；三模式共享进度（§3.4）天然落在单份玩家数据上。

**Steam Cloud 集成（方案已定，随 Steam 版实装）**：

- **选型：Auto-Cloud（自动云）为主**——Steamworks 后台配置文件规则即可，零代码；Steam 客户端负责启动前下载、退出后上传。需要精细控制（自定义同步时机/冲突 UI）时再升级 Remote Storage API（GodotSteam 的 `ISteamRemoteStorage` 接口）。
- **路径根配置**（对应上方双路径口径，Auto-Cloud 两个根都支持）：

| 规则 | Root | 子路径/文件模式 | 覆盖场景 |
|---|---|---|---|
| 便携版 | App Install Directory | `player.json`、`player.json.bak` | 打包后程序目录存档 |
| 回退版 | WinAppDataRoaming | `Godot/app_userdata/Project Sidewinder/player.json*` | `user://` 回退场景 |

- **同步范围**：只同步 `player.json`（进度跟账号走）；`settings.cfg` 不同步（画面/按键跟机器走，初值）。
- **冲突策略**：Auto-Cloud 默认时间戳新者优先；冲突时 Steam 自带对话框让玩家选本地/云；本地 `.bak` 兜底（见写入安全）。
- **开关与降级**：检测 Steam 账号/应用云开关，关闭或离线 → 纯本地存档，恢复后下次启动自动同步；设置里提供云同步开关（初值开）；编辑器运行不触云。
- **配额**：存档 <1MB，远低于 Steam Cloud 配额，无压力。
- **实装前置**：Steamworks App 后台开启 Cloud 并配置 Auto-Cloud 规则；仅 Steam 构建启用（非 Steam 构建纯本地）。

- **【待设计】**：多存档位（初版单份）、迁移函数细则。

- **【待设计】**：关卡编辑工具、性能实测标定。

## 9. MVP 范围（先验证核心乐趣）

1. 载具移动/瞄准清潮 + **单炮塔开火/武器切换** + **夺械拾取装配**（验证「战斗=刷装备」核心）。
2. **1 张多区域挑战地图**：准备室装载（1 基础 + 2 缴获武器 / 底盘 / ≤3 支援技能）+ 2–3 个区域 + 主/次目标（歼灭 + 夺取）+ 武器箱 + 可破坏地形掉资源 + 迷雾揭开（验证探索循环）+ **1–2 组挑战规则与星级评分**（验证「规则 + 分数」重玩）。
3. 武器栏预算 + 武器稀有度/词缀（验证构筑取舍）。
4. 1 个基地防守目标 + 1 个 Boss（验证高潮）。
5. 极致 Juice（震屏/命中停顿/粒子/夺械反馈）。
6. 简中 + 手柄 + Steam Deck 适配。
7. 美术管线验证：1 个 Blockbench 坦克模型 → 俯视角渲染 → 游戏内换色（验证低成本管线）。

**v0.1 垂直切片（第一版可玩，先做这个）**：

- **地图**：1 张灰盒地图（2–3 区域 + 装载覆盖层），不追求美术；可走准备室后置。
- **载具**：1 台标准底盘；武器栏 3 格（1 基础保底 + 2 缴获）；2 座基础炮塔 + 4 把缴获武器（双联机枪 / 霰弹炮 / 榴弹炮 / 电浆炮）。
- **敌人**：4 种（爬行者 / 机枪吉普 / 霰弹突击车 / 固定炮塔）+ 1 种精英变体（§4.7）。
- **目标**：歼灭 + 夺取两类，通关/失败/重开全链路（§5.11）。
- **交互**：夺械拾取/替换/粉碎换弹药、弹药箱、2 种可破坏物（砖墙/油桶）。
- **表现**：相机跟随/前瞻/边界、最小 HUD、准星、受击闪白、震屏、命中停顿。
- **不做**：存档/经济/商店/支援技能/模块/迷雾/基地防守/Boss/挑战规则/多区域流场/32 方向精灵。
- **验收**：装载 → 战斗 → 通关或失败 → 重开，10–15 分钟可完整循环；「击毁→掉落→换装→空弹自动切枪→粉碎」全链路可用；重开不残留状态；灰盒稳定 60 FPS。

**v0.1 实现顺序（建议）**：

1. `Game` Autoload + 灰盒关卡场景 + 玩家移动/相机/碰撞（§4.8、§7）。
2. 单炮塔 + 基础武器 + 子弹命中/伤害结算 + 最小 HUD（§4.2、§5.3）。
3. 4 种敌人 + 最小 AI + 死亡掉落（§4.7、§4.1）。
4. 武器栏切换 + 拾取/替换/粉碎 + 弹药储备（§5.3、§4.5）。
5. `ObjectiveManager` + 歼灭/夺取 + 通关/失败/重开（§5.11）。
6. 可破坏物（砖墙/油桶）+ 震屏/闪白/hitstop（§4.3、§6.4）。
7. 调参、灰盒跑测、按验收标准收口。

> 原则：**先做深「挑战模式」的夺械+探索+规则评分核心**，再扩展故事战役与割草模式。挑战模式 MVP 期直接开放入口，不强制先通关故事。宁可做深一个机制，也别摊薄内容。

## 10. 远期功能（后续实现）

> 以下功能**明确放到 MVP 与三模式核心循环验证之后再排期**；现在只做架构预留与口径记录，不进入开发排期。

### 10.1 多人联机（合作 PvE）

- **定位（初案）**：2–4 人合作 PvE（初值上限 4 人）；优先挑战模式共斗（目标 + 突变规则天然适合合作），其次割草模式合作生存；故事模式联机待评估；**不做 PvP**。
- **进度口径（初案）**：每人独立载具/武器库/货币账户；目标完成全队共享；关卡内掉落分配（共享先捡先得 vs 各自独立掉落）**待拍板**。
- **难度缩放（初值）**：每多 1 名玩家，敌人生命 +50%、数量 +30%。
- **技术路线**：Godot 高层多人 API（MultiplayerAPI + ENet），权威主机（host-authoritative）；Steam 联机走 Steamworks Lobby / P2P（目标平台见 §1）。
- **同步策略**：载具/武器状态低频同步 + 位置插值；子弹/特效本地表现、关键命中权威判定；大量敌人只同步状态快照（性能预算见 §7）。
- **现在的架构预留**（MVP 期即遵守，避免后期重写）：逻辑与表现分离；gameplay 事件走信号；关卡/目标状态可序列化；随机数走统一种子入口；输入抽象层（本地与远程输入同一接口）。
- **【待设计】**：掉落分配拍板、断线重连、延迟补偿、联机 UI、反作弊。

### 10.2 地图编辑器

- **定位**：可视化编辑手工地图（故事/挑战），直接产出 §5.6 关卡配置（`areas[]` / `spawn_room` / `objectives` / `loadout_rules` / `challenge_rules` / `final_area`）；**编辑器与运行时读同一份 schema**，不做两套数据。
- **功能清单（初版）**：区域划分与通道/捷径/秘密路径标注；摆放敌人/生成器/哨戒炮/可破坏物/武器箱/资源点/目标点/撤离点；准备室布局与设施开关；Boss 配置；校验（区域连通性、目标可达、装载限制合法）。
- **实现路径**：第一阶段做 Godot 编辑器内工具（@tool 插件 + 标记点节点）；第二阶段视产能做独立运行时编辑器；玩家 UGC / 创意工坊为更后期可选。
- **墙体编辑口径**：墙体以 `wall_base.tscn` 实例/预制件摆放（静态墙段、动画门、能量屏障），不用 `TileMapLayer` 画笔；`TileMapLayer` 只画背景。编辑器提供墙段/门/屏障调色板与网格吸附。
- **数据**：输出 JSON / Godot Resource 关卡配置（放 `data/`），schema 版本化。
- **【待设计】**：编辑器 UX、笔刷与区域模板库、自动校验规则、UGC 分享。
